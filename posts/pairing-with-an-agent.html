Pairing With an Agent

7 Sep 2026 · 2 min read

I resisted AI coding tools for a while. Autocomplete that guessed the next line felt like a distraction. Agents are different. They read the code, run the tests, and come back with a change. That's not autocomplete, that's a junior pair who never gets tired.

What works

  • Exploring unfamiliar code. "Where is this calculated, and who calls it?" across a large monolith used to take an hour. Now it takes a minute.
  • Writing specs. Agents are good at listing edge cases I'd skip when I'm tired.
  • Boring migrations. Renames, deprecations, the same change in forty files.

What doesn't

Agents are confident. They'll fix the symptom the ticket describes and miss the three other callers with the same bug. They'll add a new helper instead of finding the one that already exists. Left alone, they write more code than the problem needs.

So my rules are simple:

  • I explain the problem, not the solution, and ask for a plan before any code.
  • I read every line of the diff, the same as a teammate's merge request.
  • Anything touching money, permissions, or data gets my full attention, never just a glance.
The agent writes the code. I'm still the one who owns it.

The surprise has been where my time goes now. Less typing, more reading, and much more thinking about what the change should be before anyone writes it. That's probably where my time should have gone all along.
